## Prompts
PromptLayer removes code from the integration of engineering-grade techniques 
that improve building, comparing, and testing refinements to a Prompt.

### Creation
Within the home of a workspace, a new Prompt can be created by clicking "New"
then selecting "Prompt."

<Frame>
![Prompt creation access in workspace](/images/quickstart/prompt-creation-access.png)
</Frame>

A new prompt has two default Roles for the model to exhibit: "System" and
"User."

<Accordion
    icon="circle-question-mark"
    title='"User" and "System" Explained'
>
### "System"
A System Prompt is a specialized type of Prompt used in AI language models that 
sets the overall context, behavior, or persona for the AI's responses. It acts 
as a foundational instruction set that guides the model's conduct throughout an 
interaction, often without being directly visible to the end-user.

Learn more about [System Prompts](https://www.promptlayer.com/glossary/system-prompt).

### "User"
User prompts are the specific instructions or questions a user provides to an AI 
system to elicit a desired response. These Prompts are dynamic and vary with 
each interaction, reflecting the user's immediate needs and goals. They can 
range from simple requests for information to complex instructions for 
generating creative content.

Learn more about [User Prompts](https://blog.promptlayer.com/system-prompt-vs-user-prompt-a-comprehensive-guide-for-ai-prompts/#what-is-a-user-prompt).
</Accordion>

### Versioning
Each new saved edit of a Prompt creates a version. Explore ideas freely without 
losing track of what came before.

<Frame
    caption='Versions accumulated overtime to the left of a prompt.'
>
![Prompt version history display](/images/quickstart/prompt-versioning-display.png)
</Frame>

<br></br>
<Accordion
    icon="circle-question-mark"
    title='"Versioning" Explained'
>
“Versioning” is a structured practice in software engineering that tracks and 
manages the evolution of a system, document, or piece of code over time. It 
assigns identifiers, often numerical or semantic, to distinguish one iteration 
from another, allowing developers to compare, revert, and understand changes 
across the project’s history. 

**When applied to Prompt Engineering, versioning maintains a clear record of how 
Prompts change across experiments and refinements.** Each iteration is preserved 
with its own identifier, allowing engineers to trace improvements in phrasing or 
logic, revert to earlier configurations, and ensure that only the most effective 
Prompt versions are deployed to users.
</Accordion>

<Accordion

>
"Diffing" is a common software engineering mechanic that is employed to
compare two versions of some text. It isolates and visualizes the specific
additions, deletions, and modifications made, providing granular detail on 
what has changed.

modifications in a Prompt led to a different or improved AI output.**

#### Prompt Blueprint
Prompts can be exported to be utilized within other applications like ChatGPT,
Anthropic, etc. with its "Prompt Blueprint." 

<Frame
    caption='"Copy to Clipboard" provides the Prompt Blueprint'
>
![Prompt blueprint export view](/images/quickstart/prompt-blueprint-display.png)
</Frame>

<br></br>
<Accordion
    icon="info"
    title='"Prompt Blueprints" are a PromptLayer format'
>
Defined by PromptLayer, "Prompt Blueprints" format the information
that build a Prompt (e.g.: the "User" and "System" roles) by surrounding 
its text.

Excerpt from a Blueprint:
```
...
"role": "system",
"content": [
  {
    "type": "text",
    "text": "### Bakery Chatbot System Prompt \n\n#### Persona & 
             Goal\nYou are a friendly, sweet, and helpful 
             assistant...",
    ...
  }
],
...
```

Learn more about "[Prompt Blueprints](https://docs.promptlayer.com/running-requests/prompt-blueprints)"
and its format.
</Accordion>

Prompts built in PromptLayer are portable.

### Releases
Under the date is the button clickable for creating a new release label.

<Frame>
![Accessing prompt release controls](/images/quickstart/prompt-release-access.png)
</Frame>

Release labeling provides confidence to teams integrating Prompts into their 
services. 

<br></br>
<Accordion
    icon="circle-question-mark"
    title='"Release Labeling" Explained'
>
"Releases Labeling" is a process in software engineering that provides 
a structured approach to building, testing, and deploying new versions of 
software. It supports the engineering process to ensure that software is 
stable, meets quality standards, and is delivered to users efficiently.

**When applied to Prompt Engineering, release labels can guide the 
development process of Prompts to their final stage.** Labels like 
"testing," "under evaluation," or "finalized" provide clarity as Prompts 
are versioned. Labeling ensures that the correct version is being tested
or provided to users.
</Accordion>

With PromptLayer's streamlined release labeling, Prompts become:
1. Predictable, only stable versions go live. 
2. Safer, rollbacks can be instant.
3. Accountable, tying versions to outcomes and logs.

#### A/B Testing
Hovering a Prompt version reveals the "Start A/B Test" button.

<Frame>
![Starting a prompt A/B test](/images/quickstart/prompt-ab-test-display.png)
</Frame>

<br></br>
<Accordion
    icon="circle-question-mark"
    title='"A/B Testing" Explained'
>
"A/B Testing" is a method for data-driven decision-making in digital
marketing, product design, and other fields. It identifies which of two
versions of an item being tested perform better by comparing measured
user responses to both.

**When applied to Prompt Engineering, A/B testing can uncover subtle user
behavior patterns.** It can validate assumptions about phrasing or structure
and build a data-backed history of what language works best across different
contexts or models.
</Accordion>

With A/B testing initiable without the need for writing additional code, teams 
can democratize experimentation and increase their number of vetted results.

## Evals
Evaluations can be added for both Prompts and Agents.

"Evaluations" are systematic quality checks for AI systems, used to measure
and improve their performance, accuracy, reliability, and safety. They are a
set of structured processes and data used to test how well an AI performs a
specific task and to identify areas for improvement, ensuring the AI works 
as intended and meets business goals.

### Tracing
Within a workspace, Traces are viewable by clicking the "Live Logs" icon, then
navigating to "Trace" at the top of the logs. Selecting a Trace will reveal
its Spans.

<Frame>
![Trace visualization display](/images/quickstart/traces-display.png)
</Frame>

<Note>
Traces are for Agents, not Prompts
</Note>

<Accordion
    icon="circle-question-mark"
    title='"Tracing" and "Spans" Explained'
>
Tracing is a process in software engineering written to code, tracking any 
action within some software end-to-end through the system. Spans are the 
individual actions that make up a trace. Software engineers write code in 
software that specifically emit Spans to build a Trace.

**When applied to Prompt Engineering, tracing and spans visualize the reasoning
chain that form final outputs, revealing how specific components contribute to 
them.** 
</Accordion> 

### Observability
Logs and Traces are updated in real time, enabling Observability.

"Observability" is a sub-practice of software engineering, where engineers
understand a system's internal state by analyzing the external data it 
generates, such as logs, metrics, and traces.

**When applied to Prompt Engineering, observability is the basis for inferring
how to refine a Prompt and diagnose subtle issues.**

Learn more about [Observability](https://www.promptlayer.com/platform/observability).
